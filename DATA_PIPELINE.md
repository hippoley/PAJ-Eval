# Probe Player data pipeline

## Why persistence exists

A trajectory is the raw sensor for PAJ-Eval. If a public participant completes a probe and the trajectory disappears with the browser tab, the instrument cannot support replay, blinded coding, counterfactual validation, language-invariance analysis, or treatment comparison.

The production path is:

`Probe Player -> Session API -> append-only Event Store -> Evaluation Worker -> Researcher Console`

## Privacy boundary

Default research sessions are pseudonymous. Do not collect name, email, account handle, exact location, free-form identity fields, or device fingerprint for the core instrument. A random `session_id` is generated by the server. Locale is stored because it is part of measurement validity. IP addresses should not be copied into research tables or application logs beyond infrastructure requirements.

The participant must explicitly consent before server persistence begins. A local-only mode remains available for dogfood and private use.

## Tables

### sessions

- `session_id` UUID primary key
- `created_at`
- `completed_at`
- `locale`
- `consent_version`
- `instrument_version`
- `assignment_id` nullable
- `treatment_arm` nullable
- `status`

### probe_runs

- `probe_run_id` UUID primary key
- `session_id`
- `probe_family`
- `world_variant`
- `started_at`
- `completed_at`
- `terminal_action`

### events

Append-only participant behavior.

- `event_id` UUID primary key
- `session_id`
- `probe_run_id`
- `seq`
- `occurred_at`
- `elapsed_ms`
- `event_type`
- `object_id` nullable
- `payload_json`

Raw events MUST NOT contain latent construct labels.

### derived_features

Versioned output of feature extraction. Never overwrite raw events.

- `feature_id`
- `probe_run_id`
- `extractor_version`
- `feature_name`
- `feature_value`
- `evidence_event_ids`

### evaluations

- `evaluation_id`
- `session_id`
- `scoring_version`
- `construct`
- `estimate`
- `uncertainty`
- `evidence_feature_ids`
- `validation_status`

## API contract

- `POST /v1/sessions` creates a consented pseudonymous session and returns `session_id`.
- `POST /v1/sessions/{session_id}/events` appends a monotonic batch of events. Idempotency key required.
- `POST /v1/sessions/{session_id}/complete` closes the session.
- `GET /v1/research/sessions/{session_id}` is researcher-only and returns trajectory plus versioned derived layers.

The browser queues events in IndexedDB when offline and retries. The UI must visibly distinguish `saved`, `saving`, `local only`, and `save failed` states; it must never imply server persistence when no backend is configured.

## Deployment boundary

GitHub Pages is a static host and is not the durable event store. Until a real API/database deployment is configured, the public Pages build MUST operate in explicit local-only mode and allow trace export. The repository can contain the production API/schema implementation without falsely claiming that public sessions are already being collected.

Recommended production database: PostgreSQL. SQLite is acceptable for local development only. Raw events are immutable; all feature/scoring changes are versioned derivations so research results remain auditable.
